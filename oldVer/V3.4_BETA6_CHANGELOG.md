# MojModelBridge v3.4.0 Beta 7 — Ore-Only Worldgen

## Worldgen policy

Biome and dimension conversion is now disabled at every import path. This includes class-based `WorldProvider` / `BiomeGenBase` detection and resource-only `data/<modid>/biome`, `dimension`, and `dimension_type` definitions.

Village/structure-style worldgen is also disabled, including structures, structure sets, template pools, processor lists, jigsaw/placement rule resources, and copied biome modifiers. This prevents legacy village content such as source-specific boyfriend/cow village systems from entering the 1.21.1 registry layer.

## Ore generation

Ore generation is the only source worldgen that remains portable. Exact `configured_feature` + `placed_feature` resources for `minecraft:ore` are retained, placed under the target namespace, and connected with `neoforge:add_features` modifiers matching the supplied working NeoForge 1.21.1 example workspace.

Non-ore placed/configured features are removed during finalization so they cannot introduce unsupported registry dependencies.

## Validation

75 tests pass; one historical source fixture test is skipped when that fixture is not bundled in the release archive.
