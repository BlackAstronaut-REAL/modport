# MojModelBridge v3.4.0 Beta 3 — Source Fidelity Pass

This iteration focuses on source-driven behavior for the supplied NeoForge 1.21.1 target workspace.

## Included

- Crafted-item enchantment recovery from `onCraftedBy` callbacks, including same-class helper methods, emitted as native MCreator procedures and attached to item/tool elements.
- Armor stat recovery now includes the source armor enchantment table fields when statically present.
- Source `worldgen/configured_feature` + `worldgen/placed_feature` ore resources are parsed directly for exact placement counts, Y ranges, and configured vein sizes.
- Exact source ore features are bridged into NeoForge 1.21.1 with `neoforge:add_features` biome modifiers, while MCreator's duplicate ore generator is disabled for those blocks.
- Source-authored worldgen feature JSON is preserved by the resource bridge instead of being discarded.
- Added regression coverage for the real Chaos Persists source data and crafted enchantment helpers.

## Validation

- Full converter test suite: 71 passed, 1 warning.
- Real Chaos Persists content-only export: 760 content descriptors; 10 exact ore biome modifiers; 11 crafted-enchantment procedures.

## Runtime caveat

The converter's existing animation pipeline continues to preserve and bake source animation expressions, but final visual parity still requires opening the generated model/workspace in Blockbench/MCreator and running Minecraft.

- Corrected crafted-enchantment procedure generation: generated MCreator workspace metadata now declares the `itemstack` and `world` dependencies, matching the supplied working NeoForge 1.21.1 example. This fixes MCreator-generated `Procedure.execute()` calls at the source instead of patching Java after generation.
