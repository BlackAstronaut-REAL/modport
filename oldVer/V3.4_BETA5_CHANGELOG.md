# MojModelBridge v3.4.0 Beta 5 — Full Source-Fidelity Fix Pass

## Fixed

### World generation
The final worldgen cleanup now runs after non-entity content generation and compile-bridge generation. This prevents generated content from reintroducing stale `chaospersists:*_placed` references after the initial resource pass.

Exact source `placed_feature` JSON remains authoritative and is emitted under the target namespace with NeoForge biome modifiers.

### Custom item/tool models
MCreator's workspace custom model JSON under `models/<model>.json` is now the authoritative custom-model representation. MojModelBridge no longer duplicates that model under `assets/<modid>/models/custom/`, where Minecraft's vanilla ModelBakery would enforce incompatible 0..16 bounds and vanilla item rotation limits.

This preserves large Blockbench coordinates and source-authored geometry for MCreator's custom model importer.

### Block textures
Source JSON references such as `minecraft:block/diamond_ore` and `minecraft:block/oak_log` remain explicitly namespaced as vanilla resources. They are no longer converted into `cndcc:block/...` texture lookups.

### Source blocks
Source blockstates and block model files are copied and namespace-rewritten, preserving multi-variant models such as Duct Tape's `slices=0..5` state set.

### Foods
Modern clean-source constructors such as `new ItemGenericFish(4, 0.4F, false)` are now mapped to MCreator food fields.

### Tools
Source `get_*_stats(...)` values and `addToolMaterial(...)` bindings are recovered. The current Chaos Persists source yields 95 material-backed registries, including Chainsaw, Crystal Pink, and Ultimate tiers.

### Armor
Pink armor source stats and exact `pink_1.png` / `pink_2.png` layers are recovered. The layers are written in the MCreator armor path and mirrored in the source-style `textures/armor` path for compatibility with legacy texture callbacks.

### Entity variants
Ant-family source renderer registrations now preserve both shadow/visual scale and exact variant textures.
